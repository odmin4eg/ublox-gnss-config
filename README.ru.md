# ublox-gnss-config

Консольный конфигуратор **GNSS-приёмников u-blox** (M8 / M9 / M10): одной командой ставит
частоту обновления, набор созвездий, состав NMEA и навигационный профиль — и **записывает всё
во flash приёмника**, чтобы настройки пережили отключение питания.

Один Python-файл, без GUI, работает под **Windows, Linux и macOS**.

## Зачем это нужно

С завода приёмник u-blox выдаёт **1 Гц**, консервативный навигационный профиль и кучу лишних
NMEA-сообщений. Штатный способ это изменить — **u-center**, GUI под Windows. Один раз — нормально;
когда приёмников много, а машина безголовая (Raspberry Pi, промышленный ПК, сервер) или это
вообще Mac — уже больно.

Старые скрипты из интернета шлют **legacy-сообщения `CFG-*`**, которых на **M9 и M10 больше нет**.
Эта утилита работает через современный интерфейс ключей **`CFG-VALSET`**, поэтому одна и та же
команда работает на gen 8 (прошивка 3.01+), gen 9 и gen 10 — и проверяет, что записалось.

## Что делает

- **Находит** все подключённые приёмники: перебирает последовательные порты, пробует
  115200 / 38400 / 9600, опрашивает `UBX-MON-VER` и определяет поколение по `hwVersion`.
- **Применяет профиль**: частота, созвездия, версия и состав NMEA, динамическая модель,
  маска по углу места, SBAS, монитор помех, AssistNow.
- **Пишет в RAM + BBR + Flash** — настройки переживают полное обесточивание.
- **Считывает обратно** ключевые параметры, чтобы подтвердить, что они применились.
- **Показывает, что приёмник реально ловит**: тип решения, спутники в зоне видимости и в решении
  по каждой системе, C/N0, значения DOP, координаты, оценку точности — плюс статистику канала
  (байт/с, % загрузки линии, битые контрольные суммы, частоты по типам сообщений).
- Сам обходит ограничения поколений (см. [Ограничения по созвездиям](#ограничения-по-созвездиям)).

## Поддерживаемое железо

| Поколение | `hwVersion` | Типичные модули | Статус |
|---|---|---|---|
| **M10** | `000A0000` | MAX-M10S, MIA-M10, SAM-M10Q, NEO-M10 | полностью поддерживается |
| **M9** | `00190000` | ZED-F9P/F9R (как обычный приёмник), NEO-M9N | полностью поддерживается |
| **M8** | `00080000` | NEO-M8N/M8U, CAM-M8 | поддерживается при protver >= 27 (прошивка 3.01+) |
| M6 / M7 / M8 со старой прошивкой | — | NEO-6M, NEO-7M | **не поддерживается** — нет `CFG-VALSET`, только u-center |

Подключение: **нативный USB** приёмника (CDC-ACM) либо его **UART** через любой USB-мост
(PL2303, CP210x, CH340/CH341, FTDI).

## Установка

Нужен **Python 3.10+**. Ограничение 3.10 идёт от `pyubx2`/`pynmeagps`, а не от самой утилиты.

### Любая ОС — как пакет (рекомендуется)

```bash
pipx install git+https://github.com/odmin4eg/ublox-gnss-config
# или: pip install git+https://github.com/odmin4eg/ublox-gnss-config
ublox-setup --list
```

Подтянет [`pyserial`](https://pypi.org/project/pyserial/) и
[`pyubx2`](https://pypi.org/project/pyubx2/) и даст команду `ublox-setup`.

### Любая ОС — одним файлом, без установки

```bash
pip install pyserial pyubx2
curl -L -O https://raw.githubusercontent.com/odmin4eg/ublox-gnss-config/main/ublox_setup.py
python3 ublox_setup.py --list          # в Windows: python ublox_setup.py --list
```

Всё, что ниже — детали по конкретной ОС, нужные только если порт не появляется.

### Windows: на что смотреть

- Python ставьте с [python.org](https://www.python.org/downloads/) — в установщике обязательно
  отметьте **«Add python.exe to PATH»**.
- **Драйверы.** Windows 10/11 сама видит нативный USB u-blox, а также CP210x и FTDI.
  Для дешёвых **PL2303** и **CH340** может понадобиться драйвер производителя
  ([CH340](https://www.wch-ic.com/downloads/CH341SER_EXE.html),
  [PL2303](https://www.prolific.com.tw/US/ShowProduct.aspx?p_id=225&pcid=41)).
  Проверьте **Диспетчер устройств → Порты (COM и LPT)**: порт должен быть без жёлтого «!».
- **Закройте u-center перед запуском** — Windows даёт эксклюзивный доступ к COM-порту,
  а u-center его удерживает.

### Linux: на что смотреть

**Права на порт.** Без этого будет `Permission denied: '/dev/ttyUSB0'`:

```bash
sudo usermod -aG dialout $USER     # Debian/Ubuntu; в Arch/Fedora группа называется 'uucp'
# перелогиньтесь (или: newgrp dialout), чтобы группа применилась
```

**Если запущен `gpsd`**, он держит порт и будет соперничать за него, а его драйвер u-blox
умеет переставлять частоту в RAM. Остановите:

```bash
sudo systemctl stop gpsd gpsd.socket
```

В свежих дистрибутивах (PEP 668, например Ubuntu 24.04) системный pip запрещён — используйте
`pipx` (см. выше) или venv:

```bash
python3 -m venv ~/.venvs/ublox && ~/.venvs/ublox/bin/pip install pyserial pyubx2
~/.venvs/ublox/bin/python ublox_setup.py --list
```

### macOS: на что смотреть

Драйверы для нативного USB u-blox, CP210x и FTDI встроены в систему (начиная с Big Sur).
Для CH340 и старых клонов PL2303 драйвер нужен.

Всегда используйте устройство **`/dev/cu.*`**, а не `/dev/tty.*`: `tty.*` блокируется в ожидании
сигнала несущей. Утилита при сканировании сама предпочитает `cu.*`.

## Быстрый старт

**Просто настроить типовой автомобильный приёмник как надо:**

```bash
ublox-setup --yes
```

Это всё. Значения по умолчанию **и есть** рекомендуемый автомобильный профиль: 10 Гц, все
созвездия, которые чип тянет одновременно, NMEA 4.1 с нужными сообщениями и отключёнными
лишними, динамическая модель automotive, маска 10° по углу места, поправки SBAS, монитор помех
и AssistNow включены, запись во flash. Приёмник найдётся сам, профиль подстроится под поколение,
а в конце напечатается отчёт по спутникам — видно, что всё работает.

Остальное — вариации того же:

```bash
# что вообще подключено?
ublox-setup --list

# интерактивно: спросит частоту и созвездия, настроит всё найденное
ublox-setup

# конкретный приёмник, 5 Гц, пешеходный профиль
ublox-setup --port /dev/ttyUSB0 --rate 5 --dynmodel pedestrian --yes

# посмотреть, что будет отправлено, ничего не трогая
ublox-setup --dry-run

# примерить без записи во flash (откатится при отключении питания)
ublox-setup --no-save --yes

# просто посмотреть на приёмник: решение, спутники, уровни сигнала в реальном времени
ublox-setup --monitor --port COM3

# только проверить уже настроенный приёмник
ublox-setup --check 10 --port /dev/ttyUSB0
```

## Ключи командной строки

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `--list` | — | вывести список портов (устройство, VID:PID, серийник, предполагаемый тип) и выйти |
| `--port PORT` | все найденные | настроить конкретный порт вместо сканирования |
| `--rate HZ` | `10` | частота навигационного решения и вывода, 1–25 Гц |
| `--systems LIST` | все | список через запятую: `GPS,GLO,GAL,BDS,QZSS,SBAS` |
| `--talker gp\|gn` | `gp` | основной talker ID: `$GPxxx` или стандартный мульти-GNSS `$GNxxx` |
| `--dynmodel NAME` | `automotive` | `portable`, `stationary`, `pedestrian`, `automotive`, `sea`, `airborne1g/2g/4g` |
| `--min-elev DEG` | `10` | маска по углу места — игнорировать спутники ниже этого угла |
| `--min-cno DBHZ` | заводское (6) | маска по уровню сигнала — отбрасывать спутники слабее |
| `--max-pdop PDOP` | заводское (25.0) | не выдавать решение, если PDOP хуже этого |
| `--max-tdop TDOP` | заводское (25.0) | не выдавать решение, если TDOP хуже этого |
| `--iface auto\|uart1\|usb\|both` | `auto` | какому интерфейсу приёмника настраивать вывод NMEA |
| `--baud N` | `115200` | целевая скорость UART1 |
| `--no-save` | выкл | применить только в RAM (тест, откатится при отключении питания) |
| `--dry-run` | выкл | напечатать все пары ключ/значение, ничего не отправляя |
| `--monitor [SEC]` | — | живой вид: решение, спутники, уровни; выход по Ctrl-C |
| `--check [SEC]` | `5` | одноразовый отчёт по уже настроенному приёмнику, ничего не настраивает |
| `--no-check` | выкл | не показывать отчёт после настройки |
| `--raw` | выкл | добавить в отчёт несколько сырых строк NMEA |
| `--yes` | выкл | без вопросов и подтверждений (для скриптов и CI) |

Коды возврата: **0** успех · **1** ничего не найдено или ошибка аргументов ·
**2** приёмник не применил конфигурацию до конца.

## Почему talker по умолчанию `GP`

При нескольких включённых созвездиях u-blox отдаёт `$GNGGA` / `$GNRMC` (GN = смешанное решение).
Удивительно много потребителей — головные устройства на Android, старые логгеры, самописные
парсеры, часть навигационных приложений — фильтруют строго `GPGGA` / `GPRMC` и при `GN` молча
показывают **отсутствие координат**. Принудительный `GP` это чинит.

Если ваш софт корректно работает со стандартом и вам нужны настоящие мульти-GNSS talker'ы,
используйте `--talker gn`. В обоих случаях сообщения `GSV` сохраняют собственный talker
(`$GPGSV`, `$GLGSV`, `$GAGSV`, …), поэтому разбивка спутников по системам в отчёте остаётся.

## Полный справочник применённых настроек

Каждая группа = один `CFG-VALSET`. Ключи pyubx2 даны с подчёркиваниями.

### GNSS — выбор созвездий (`CFG_SIGNAL_*`)

| Ключ | Знач. | Что делает | Что даёт |
|---|---|---|---|
| `CFG_SIGNAL_GPS_ENA` + `_GPS_L1CA_ENA` | 1 | GPS L1 C/A | базовая система, обязательна |
| `CFG_SIGNAL_GLO_ENA` + `_GLO_L1_ENA` | 1 | ГЛОНАСС L1OF | лучшее покрытие в РФ и высоких широтах, +спутники |
| `CFG_SIGNAL_GAL_ENA` + `_GAL_E1_ENA` | 1 | Galileo E1 | высокая точность, +спутники |
| `CFG_SIGNAL_BDS_ENA` + `_BDS_B1_ENA` | 1 | BeiDou B1I | +спутники (**только M9**; на M10 конфликтует с ГЛОНАСС → выключен) |
| `CFG_SIGNAL_QZSS_ENA` + `_QZSS_L1CA_ENA` | 1 | QZSS L1 | региональное усиление GPS, не мешает |
| `CFG_SIGNAL_SBAS_ENA` + `_SBAS_L1CA_ENA` | 1 | SBAS | приём дифференциальных поправок |

**Зачем все сразу:** больше видимых спутников → лучше геометрия (ниже DOP) → быстрее и
устойчивее решение, особенно в городе и под деревьями.

### NAV — навигационный движок (`CFG_NAVSPG_*`)

| Ключ | Знач. | Что делает | Что даёт |
|---|---|---|---|
| `CFG_NAVSPG_DYNMODEL` | 4 = automotive | модель динамики «автомобиль» (фильтр настроен на горизонтальное движение) | гладкий и точный трек, меньше выбросов на скорости |
| `CFG_NAVSPG_INFIL_MINELEV` | 10° | игнорировать спутники ниже 10° над горизонтом | отсекает многолучёвость (отражения от зданий) → точнее |

Значение динамической модели меняется ключом `--dynmodel`, маска — ключом `--min-elev`.

### RATE — частота решения (`CFG_RATE_*`)

| Ключ | Знач. | Что делает | Что даёт |
|---|---|---|---|
| `CFG_RATE_MEAS` | 100 мс | период измерений = 10 Гц | 10 точек/с: плавный трек, точная привязка событий к координате |
| `CFG_RATE_NAV` | 1 | навигационное решение на каждое измерение | без прореживания решений |

### NMEA — формат вывода (`CFG_NMEA_*`)

| Ключ | Знач. | Что делает | Что даёт |
|---|---|---|---|
| `CFG_NMEA_PROTVER` | 41 (4.1) | версия протокола NMEA 4.1 | корректные talker ID для Galileo/BeiDou, расширенные поля |
| `CFG_NMEA_HIGHPREC` | 1 | больше знаков после запятой в координатах | повышенная точность вывода |
| `CFG_NMEA_MAINTALKERID` | 1 (GP) | основные сообщения с префиксом `$GP` | совместимость со старыми парсерами (см. выше) |
| `CFG_NMEA_GSVTALKERID` | 0 | GSV сохраняет talker своей системы | без этого разбивка спутников по созвездиям схлопнулась бы в одну строку |

### SBAS — дифференциальные поправки (`CFG_SBAS_*`)

| Ключ | Знач. | Что делает | Что даёт |
|---|---|---|---|
| `CFG_SBAS_USE_RANGING` | 1 | использовать SBAS-спутники как дальномерные | +спутники в решении |
| `CFG_SBAS_USE_DIFFCORR` | 1 | применять дифференциальные поправки (ионосфера и т.д.) | выше точность |
| `CFG_SBAS_USE_INTEGRITY` | 1 | использовать данные целостности | отбраковка ненадёжных измерений |

PRN-маска оставлена по умолчанию — все системы, включая WAAS, EGNOS, MSAS и российскую SDCM.

### ITFM — монитор помех (`CFG_ITFM_*`)

| Ключ | Знач. | Что делает | Что даёт |
|---|---|---|---|
| `CFG_ITFM_ENABLE` | 1 | детектор узкополосных (CW) и широкополосных помех | приёмник видит и подавляет наводки и глушилки (дешёвые зарядки, GPS-jammer) → устойчивее в машине |

Пороги `CFG_ITFM_BBTHRESHOLD` (3) и `CFG_ITFM_CWTHRESHOLD` (15) оставлены заводскими.

### AssistNow (`CFG_ANA_*`)

| Ключ | Знач. | Что делает | Что даёт |
|---|---|---|---|
| `CFG_ANA_USE_ANA` | 1 | AssistNow Autonomous — приёмник сам прогнозирует орбиты | быстрый повторный захват (TTFF) после потери: тоннель, мост, парковка |

### MSGOUT — какие NMEA-сообщения и как часто

Ключи `CFG_MSGOUT_NMEA_ID_*_UART1` и/или `*_USB` — в зависимости от `--iface`.

| Сообщение | Частота | Содержит | Зачем |
|---|---|---|---|
| `GGA` | 10 Гц | позиция, высота, число спутников, качество решения | основной источник координат |
| `RMC` | 10 Гц | позиция, скорость, курс, дата/время | скорость и время |
| `VTG` | 10 Гц | курс и скорость относительно земли | дополнительные данные движения |
| `GST` | 10 Гц | статистика ошибок (оценка погрешности) | контроль точности |
| `GSA` | ~2 Гц | активные спутники + DOP | геометрия, меняется медленно → прорежено |
| `GSV` | ~2 Гц | спутники в зоне видимости | диагностика и индикация; объёмное → прорежено |
| `GLL, GNS, ZDA, GBS, DTM, GRS, VLW` | 0 (выкл) | дубли и служебное | экономия канала |

**Прореживание GSA/GSV** (делитель ≈ частота/2) — чтобы 10 Гц со всеми созвездиями влезли в
115200 без переполнения.

### UART / USB — транспорт

| Ключ | Знач. | Что делает | Что даёт |
|---|---|---|---|
| `CFG_UART1_BAUDRATE` | 115200 | скорость порта | пропускная способность для 10 Гц мульти-GNSS с запасом |
| `CFG_UART1INPROT_UBX` / `_NMEA` | 1 / 1 | приём команд в UBX и NMEA | можно переконфигурировать по тому же проводу |
| `CFG_UART1OUTPROT_NMEA` | 1 | вывод NMEA | для потребителя данных |
| `CFG_UART1OUTPROT_UBX` | 1 | вывод UBX | опрос настроек, ACK, проверка |
| `CFG_USBINPROT_*` / `CFG_USBOUTPROT_*` | 1 | то же самое для нативного USB-интерфейса | приёмник, подключённый по USB, тоже отдаёт настроенный поток |

### Намеренно оставлено по умолчанию

| Параметр | Текущее | Почему не трогаем |
|---|---|---|
| `CFG_NAVSPG_OUTFIL_PDOP` / `_TDOP` | 250/250 (= 25.0/25.0) | заводское значение и так соответствует «мягкой» рекомендации для авто; жёсткая маска приводит к потере решения в тоннелях и дворах |
| `CFG_NAVSPG_INFIL_MINCNO` | 6 dBHz | популярные гайды предлагают 10–15, но для движущегося автомобиля важнее **удержать** слабые спутники; шум и так режется отсечкой по углу места 10° |

Если всё же хотите значения из гайда — на каждый параметр есть ключ, и без него в приёмник
ничего не пишется:

```bash
ublox-setup --yes --min-cno 12 --max-pdop 10 --max-tdop 10
```

### Слои сохранения

`CFG-VALSET` пишется в `layers = RAM | BBR | Flash` (битовая маска 7):

- **RAM** — действует сразу;
- **BBR** (Battery-Backed RAM) — переживает программный сброс при наличии резервной батарейки;
- **Flash** — переживает **полное обесточивание**. Именно поэтому настройки сохраняются после
  выключения питания. Ключ `--no-save` пишет только в RAM.

## Ограничения по созвездиям

- **M9** тянет все шесть систем одновременно: GPS + ГЛОНАСС + Galileo + BeiDou + QZSS + SBAS.
- **M10** (одночастотный) **не может одновременно ГЛОНАСС и BeiDou** — это аппаратное
  ограничение, приёмник просто отвечает NAK. Утилита определяет поколение и **отключает BeiDou,
  оставляя ГЛОНАСС**, о чём печатает предупреждение. Если BeiDou важнее, укажите явно:
  `--systems GPS,BDS,GAL,QZSS,SBAS`.

## Пропускная способность

10 Гц с несколькими созвездиями — это заметный поток. Утилита оценивает нагрузку до записи и
предупреждает, если она превышает ~80% линии, а отчёт после настройки показывает фактическую.
Замер на M10, 10 Гц, UART 115200, пять созвездий: **~17% загрузки канала, 0 битых контрольных
сумм, 0 обрезанных строк**.

Если поднять частоту или опустить скорость порта так, что оценка уйдёт за 100%, сообщения
**будут обрезаться**. Лечится повышением `--baud`, понижением `--rate` или отключением
части созвездий.

## Диагностика

| Симптом | Причина / решение |
|---|---|
| `--list` не показывает портов | кабель только для зарядки; нет драйвера (Диспетчер устройств в Windows); в Linux посмотрите `dmesg \| tail` сразу после подключения |
| `Permission denied: '/dev/ttyUSB0'` | добавьте себя в группу `dialout` (или `uucp`) и перелогиньтесь |
| `Access is denied` на COM-порту (Windows) | порт держит u-center или другая программа — закройте её |
| `no u-blox response` на существующем порту | это другое устройство; либо приёмник на нестандартной скорости (утилита пробует 115200/38400/9600); либо на macOS вы обратились к `/dev/tty.*` вместо `/dev/cu.*` |
| Настройки применились, но частота вернулась к 1 Гц | приёмник переконфигурирует кто-то ещё в рантайме — так делает драйвер u-blox в `gpsd` (в RAM). Наши настройки лежат во flash и вернутся после перезагрузки питания; остановите `gpsd` или перезапустите утилиту после него |
| Все группы `OK`, но решения нет | вы в помещении. Холодный старт требует ~30 с открытого неба. `--monitor` показывает спутники в зоне видимости даже без решения: если значения C/N0 появляются — с антенной всё в порядке |
| `gen 8 ... needs the legacy CFG-* interface` | прошивка старше 3.01 — используйте u-center или обновите прошивку |
| Частота выросла, но строки «рваные» | канал перегружен — см. [Пропускная способность](#пропускная-способность) |

## Безопасность

- По умолчанию всё пишется во **flash**. Чтобы примерить, используйте `--no-save`: после
  выключения питания вернётся прежняя конфигурация.
- Утилита не трогает прошивку и не может «окирпичить» приёмник. Худшее, что может случиться —
  вы запишете конфигурацию, которая вам не нравится; перезапустите с другими ключами или
  сделайте сброс к заводским настройкам из u-center.
- Когда связь идёт по тому самому UART, который перенастраивается, смена скорости применяется
  **первой**, после чего порт переоткрывается на новой скорости. Если прервать утилиту ровно в
  этот момент, приёмник останется на новой скорости, а вы будете ждать старую — просто
  запустите заново, определение перебирает несколько скоростей.
